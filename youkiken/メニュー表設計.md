# 陽気軒 メニュー表改訂 設計書

最終更新：2026-09-09

## 1. 背景と目的

陽気軒からメニュー表改訂の依頼を受けている。主な内容は以下のとおり。

- 商品の入れ替え（削除・新規追加）と値段の見直し
- **お持ち帰りメニュー**の追加
- **特盛**の追加
- 持ち帰りできる品・特盛にできる品を、メニュー表の中で視覚的にわかりやすく示したい

検討は店員さんと一緒に Google スプレッドシートを見ながら進める。

## 2. 検討フロー（全体像）

```
menu.json（現行データ）
   ↓ GASで転記
Googleスプレッドシート「陽気軒 メニュー改訂検討」
   ↓ 店員さんと記入・検討
確定した改訂内容
   ↓ 反映
menu.json ＋ サイト（バッジ表示）＋ 紙のメニュー表
```

- タブ構成：**使い方／平日（107品）／土日祝（78品）**
- 列構成：

| 列 | 内容 | 入力方式 |
|---|---|---|

## 4. 事前調査の結果（事実）

- テイクアウト可を示す**公的な標準図記号（JIS Z8210等）は存在しない**。各店が独自デザインで運用している
- 流通しているテイクアウトアイコンは「家」「紙袋」「スプーン＆フォーク」モチーフで**赤・オレンジの暖色系**が主流。「テイクアウトOK」と文字を入れた素材も多い
- オレンジは「食を連想・温かみ・親しみ」の色として飲食店ロゴで多用される
- 「特盛」は牛丼チェーン（すき家：ミニ〜メガの6サイズ＋口頭注文のキング）ではマークではなく**サイズ展開として料金列に並べる**方式
- メニューブック制作の実務では、**①凡例を目立つ位置に掲載して意味を統一、②アイコンの種類を限定して乱立を防ぐ、③視覚（アイコン）＋言語（文字）の二層で伝える**ことが推奨されている
- 大手チェーンの紙メニュー上のマーク様式はウェブ非公開で確認できず

## 5. マーク（バッジ）の設計方針

### 決定済みの骨格

- メニュー名の横にマーク、**右上に四角枠の凡例**（アイコン＋短い説明の二層）
- 持ち帰り可・特盛可は**品によって異なるのでマークで表示**
- **大盛りは全品対象なのでアイコン化せず、凡例の説明文のみ**（アイコン乱立防止）
  ※説明文は条件込みで書く：「麺類大盛り：平日無料・土日祝＋200円」「ご飯類・スープ大盛り＋200円」
- 抽象アイコンではなく**文字入りバッジ**（客層に年配の方が多いため）
- 色＋文字で区別（白黒印刷・色覚多様性対応）。マークは「人気」「名物」と合わせて**4種上限**
- 既存タグとの描き分けルール：**枠線＝おすすめ情報（人気・名物）／塗りつぶし＝注文オプション（持ち帰り・特盛）**

### 初版デザイン（ChatGPT/Codex生成）とレビュー

- 受領物：`Codex 画像 2026年9月8日 07_20_12.svg`（Downloads内）。「持」＝#E8780A、「特盛」＝#C8920A の角丸正方形バッジ凡例見本
- 3つの観点（視覚デザイン／印刷・実装／UX・情報設計）で独立レビューを実施。**土台（文字入りバッジ・角丸・暖色・描き分け）は3者とも評価**、以下の修正が必要と結論：

| 問題（全観点共通） | 内容 |
|---|---|
| コントラスト不足 | 白文字 on #E8780A≒3.0:1、on #C8920A≒2.6:1 でWCAG大文字基準未満 |
| 「特盛」が小サイズで潰れる | 正方形に2文字は行内サイズ（高さ14px／6〜8pt）で判読不能 |
| 白黒コピーで2色の区別が消える | 2色の明度がほぼ同一（グレー化すると同じ約60%グレー） |
| 見本のまま使えない | 背景枠・ラベル入りの凡例見本。単体切り出し＋文字アウトライン化が必要。`dominant-baseline`とシステムフォント依存で環境により文字ずれ |

| 観点別の重要指摘 | 内容 |
|---|---|
| UX：誤読リスク | 「特盛」バッジは「これは特盛だ」と誤読され、追加料金の会計トラブルに直結 → 文言を「特盛可」に |
| UX：凡例の消失 | Webはスクロールで凡例が画面外に → sticky領域直下に1行常設＋末尾再掲 |
| UX：付与率 | 持ち帰り可が7割超なら、バッジをやめて「◯◯を除く全品お持ち帰りできます」の逆転表記に切り替える |
| 実装：CSS推奨 | Webは画像を使わず既存 `.tag` クラス拡張のCSSバッジで実装。SVGは紙用のみ |
| 印刷 | 入稿時はCMYK値指定＋色校正。小サイズ規定（バッジ最小高さ10pt目安） |

### 修正方針（レビュー統合後の現行案）

| 項目 | 初版 | 修正案 |
|---|---|---|
| 文言 | 持／特盛 | **持帰／特盛可** |
| 形状 | 両方正方形 | 持帰＝正方形、特盛可＝**横長角丸**（文字の見た目サイズを揃える） |
| 色 | #E8780A／#C8920A | 一段暗く：持帰 **#C2410C**、特盛可 **#7A4A18**（サイト既存の --brown。どちらも白文字4.5:1超、白黒でも明度差が出る） |
| Web実装 | SVG画像 | CSSバッジ（menu.json の tags 連動） |
| 紙用 | 見本のまま | 単体SVG＋文字アウトライン化＋CMYK指定 |
| 凡例 | 右上のみ | 紙＝各ページ右上／Web＝sticky直下に常設＋末尾再掲 |

- 並び順ルール：**メニュー名 → 名物/人気 → 特盛可 → 持帰 → 価格**（常に同順）

### v2バッジ（修正版）の受領と検証結果

修正方針を反映した v2 一式を受領し、[badges/](badges/) に取り込み済み。検証結果：

- レンダリング確認OK（「持帰」48×48、「特盛可」76×48、文字アウトライン化済みで鮮明）
- コントラスト実測：白 on #C2410C＝**5.18:1**、白 on #7A4A18＝**7.45:1**（WCAG 4.5:1クリア）
- 白黒コピー対策OK（相対輝度 0.153 vs 0.091 で明度差あり）
- CMYK指定値（C0 M66 Y94 K24／C0 M39 Y80 K52）は検算済み。ただしSVG内の記載は覚え書きであり、**入稿時のCMYK変換工程は別途必要**
- **紙用SVG 2点はこのまま採用可**
- **Web用CSS/JS（web-menu-badges.*）は参考実装扱い**。現行 index.html はメニュー行をテンプレート文字列（`.menu-row`／`.tag`）で描画しており、v2のJS（`.menu-heading` 前提のESモジュール）はそのままでは動かない。実装時は既存レンダラの tags 処理にクラス出し分けと並び替えを追加する（最小改修）。バッジ高さも既存タグの寸法感（0.72rem系）に合わせて縮小する

### 凡例の文言案（紙・各ページ右上）

```
┌ マークのご案内 ─────────────────┐
│ 特盛可 … 特盛にできます（＋◯円）        │
│ 持帰  … お持ち帰りできます              │
│ ※麺類大盛りは平日無料・土日祝＋200円     │
└─────────────────────────┘
```

特盛の追加料金が未定の間は「（＋◯円）」を出さず「別途追加料金」と表記し、確定後に差し替える。

## 6. サイトへの反映方法（後工程）

- [menu.json](menu.json) の各品の `tags` に `"持ち帰り可"` `"特盛可"` を追加（既存の `"人気"` `"名物"` と同じ仕組み）
- [index.html](index.html) の `.tag` クラスにモディファイアを追加してCSSバッジ表示（例：`.tag--takeout { background:#C2410C; color:#fff; }`）
- 凡例：sticky領域（タブ・カテゴリチップ）直下に1行常設＋ `menu-foot-note` に再掲
- お持ち帰り専用の新メニューが出る場合は、カテゴリ追加かタグ運用かを検討時に決める

## 7. 紙のメニュー表 作成フロー（ラミネートまで）

現物の仕様（HANDOFF.md の撮影記録より）：**平日1枚＋土日祝1枚、各表裏印刷、ラミネート加工**。改訂版も同仕様を踏襲する。

### 紙面の決定事項・未定事項

- **縁（フチ）のデザイン：中華のラーメンどんぶり柄（雷文＝渦巻き模様）で囲む**
- **ラミネートは外部業者に送って加工してもらう**（下記2案のB案で確定）
- **用紙サイズは A3（297×420mm）か B4（257×364mm）の2択に絞る**（2026-09-08決定）。最終決定は現物の実寸確認（店長に測ってもらう or 基準物入り写真）を待って行う。どちらもネット印刷・ラミネート外注の標準対応サイズ
  - 参考：画用紙規格（八つ切り271×392／四つ切り392×542）はA・B判と別規格のため不採用
- **新メニューは店から手書きメモの写真をもらって内容を起こす**（清書・価格確認はこちらで実施）

```
① 内容確定        スプシ検討完了 → 品目・価格・持帰/特盛チェック・特盛料金を確定
② データ反映      menu.json 更新（tags追加）→ サイトで内容の正しさを先に検証
③ 版下作成        紙面デザイン（バッジ・右上凡例を配置。文字はアウトライン化、CMYK指定）
④ 内容校正        店主・店員さんチェック（誤字・価格・マーク付け忘れ）→ 修正
⑤ 色校正/試し刷り  バッジ2色の発色・小サイズの潰れを実物で確認 → 必要なら色調整
⑥ 本印刷          平日・土日祝 × 表裏 = 4面。耐水性を考えるならコート紙
⑦ ラミネート加工   下記2案のどちらか
⑧ 店舗設置        旧メニューと差し替え。サイト公開と同日に揃える
```

- 校正は**④内容→⑤色の2段階**を想定（回数・納期は未確定。決まったらここに記入）
- ②を⑥より先にやるのがポイント：サイトは即時修正できるので、紙の刷り直しリスクを減らせる

### 版下の作成方式（2026-09-09決定）

複数候補（HTML/CSS→PDF・Typst・Illustrator等の手動DTP・Scribus・画像生成AI）を比較検討し、批判的レビューを経て以下に決定。

**決定：版下は HTML/CSS＋menu.json のデータ駆動で組み、Chromeヘッドレス印刷でPDF化する。CMYK変換（PDF/X-1a化）は業者の入稿仕様が要求する場合のみ press-ready で後付けする。**

```
【最優先】業者確定 → 入稿仕様書を読む（RGB可否・トンボ要否・塗り足し）
    ↓
menu.json → 版下HTML（仕上がり寸＋塗り足し3mmの固定サイズ、あふれ検出付き）
    ↓
Chromeヘッドレス印刷 → PDF（フォント埋め込み・枯れた経路）
    ↓ 業者がRGB PDF可 → そのまま入稿（変換工程ゼロ）
    ↓ PDF/X必須       → press-ready で変換
    ↓
ダミー1面で入稿形式まで通す「パイプライン検証」を初日に実施
（プリントネットなら無料の自動データチェックに実際に通して合否確認）
```

選定理由と検討経緯：

- **HTML/CSS方式にした理由**：店主の「ここをこう変えて」に対し、menu.json や CSS を直して再生成するだけで数分で回せる唯一の方式。サイトと紙が menu.json という単一データ源を共有でき、価格の転記ミスが構造的に起きない。採用済みの紙用バッジSVG（badges/）もそのまま埋め込める
- **他候補の不採用理由**：Typst＝PDF/X対応が未成熟・雷文などの装飾が作りにくい／Illustrator等の手動DTP＝部分修正のたびに手作業が発生しAI反復と矛盾／Scribus＝XML直接編集が壊れやすく反復速度で劣る／画像生成AI＝100品超の品名・価格の正確性を担保できない（部品の下書き用途に限定）
- **出力経路の設計方針**：当初案の Vivliostyle+press-ready 常用は、ニッチなツールチェーンが土壇場で動かないリスク（差し戻し即アウトのスケジュール）を考慮して主役から降格。一番壊れにくい経路を基本にし、凝った変換は業者が要求したときだけ使う
- **順序の原則**：入稿要件は業者ごとに違う（RGB入稿可の業者ならCMYK変換自体が不要）ため、**方式の作り込みより業者確定が先**。業者仕様が出た時点で版下テンプレートに着手する
- **CMYKの扱い**：バッジのCMYK指定値に自動変換で厳密一致させることは求めない。ラミネートされる店内メニューで必要なのは判読性とコントラストであり、発色は試し刷り（工程⑤）で実物確認する
- **リスク対策**：①固定4面レイアウトのため品目増による行あふれを検知する仕組みを版下に入れる、②本番データ作成前にダミー1面で入稿チェックまで一往復して経路を実証する

### ラミネートの2案

| 案 | 方法 | 特徴 |
